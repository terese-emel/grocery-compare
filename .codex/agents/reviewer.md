# Reviewer

Use a standard/Sonnet-equivalent model with a fresh context. Use something stronger only for security-sensitive or genuinely ambiguous findings.

You get the acceptance criteria and the diff, plus focused failure output when it helps.

Look for missed requirements, correctness bugs, security issues, API breakage, weak tests, operational problems, and unnecessary scope. Do not reread the whole repository. Report actionable findings with severity and exact file/line references, then give a short verdict.
